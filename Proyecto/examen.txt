Examen de TypeScript y tsc
Dificultad media — 30 preguntas
Versión para alumnado, sin respuestas marcadas.

1. ¿Cuál es la función principal de TypeScript dentro de un proyecto JavaScript moderno?


B. Añadir comprobación de tipos y mejorar el desarrollo antes de generar JavaScript


2. ¿Qué ocurre normalmente al ejecutar tsc en un proyecto con tsconfig.json?


A. TypeScript busca la configuración del proyecto y compila según esas opciones


3. ¿Qué opción de tsconfig.json se usa para indicar la versión de JavaScript de salida?


B. target


4. ¿Qué opción indica el sistema de módulos generado en la salida JavaScript?


A. module


5. ¿Qué efecto tiene "strict": true?


B. Activa un conjunto más exigente de comprobaciones de tipos


6. ¿Cuál es la diferencia principal entre any y unknown?


A. any permite operar sin comprobaciones; unknown exige comprobar el tipo antes de usarlo


7. ¿Qué hace una aserción de tipo como valor as string?


B. Indica al compilador que trate ese valor como string


8. ¿Qué representa el tipo never?


C. Un valor que no debería llegar a producirse nunca


9. ¿Cuál de estas funciones está correctamente tipada?


A. function suma(a: number, b: number): number { return a + b; }


**10. ¿Qué significa esta unión de tipos?

let id: number | string;**


A. id puede guardar un número o una cadena


11. ¿Qué es el narrowing en TypeScript?


A. El proceso de reducir un tipo amplio a uno más concreto mediante comprobaciones


12. ¿Cuál de estos ejemplos aplica narrowing correctamente?


A. if (typeof valor === "string") { valor.toUpperCase(); }


**13. ¿Para qué sirve interface en este ejemplo?

interface Producto { id: number; nombre: string; }**


A. Para describir la forma que debe tener un objeto Producto


14. ¿Qué diferencia general hay entre type e interface?


A. Ambas pueden describir formas de datos, pero type también puede definir uniones, alias y tipos más compuestos


15. ¿Qué hace import type?


A. Importa algo solo para usarlo como tipo, sin necesidad de mantenerlo como importación de runtime


16. ¿Qué opción de tsconfig.json evita generar archivos JavaScript aunque se revisen los tipos?


A. noEmit


17. ¿Qué opción permite generar archivos .d.ts al compilar?


A. declaration


18. ¿Para qué sirven los archivos .d.ts?


A. Para describir tipos sin incluir implementación JavaScript


**19. ¿Qué significa esta definición genérica?

function obtener<T>(valor: T): T { return valor; }**


A. La función conserva el tipo del valor recibido y devuelve ese mismo tipo


**20. ¿Qué expresa esta restricción genérica?

function leer<T, K extends keyof T>(obj: T, clave: K) { return obj[clave]; }**


A. Que clave debe ser una propiedad válida de obj


21. ¿Qué significa que una propiedad sea opcional en una interfaz?


B. Que puede no aparecer en algunos objetos de ese tipo


22. ¿Cuál de estas interfaces define correctamente una propiedad opcional?


A. interface Tarea { titulo?: string; completada: boolean; }


23. ¿Qué significa readonly en una propiedad de TypeScript?


B. Que la propiedad no puede modificarse después de ser asignada


24. ¿Qué hace sourceMap en tsconfig.json?


A. Permite generar mapas para relacionar el JavaScript compilado con el TypeScript original


25. ¿Qué significa lib dentro de compilerOptions?


A. La lista de bibliotecas de tipos disponibles para el proyecto, como DOM o versiones de ECMAScript


26. ¿Qué permite hacer allowJs?


A. Permite que el compilador tenga en cuenta archivos .js además de archivos .ts


27. ¿Qué permite hacer checkJs?


A. Comprobar tipos también en archivos JavaScript, normalmente con ayuda de JSDoc


28. ¿Qué ocurre con los tipos de TypeScript en tiempo de ejecución?


B. Desaparecen al compilar porque sirven para el análisis del compilador


29. ¿Qué ventaja aporta keyof?


A. Permite obtener un tipo formado por las claves de otro tipo u objeto


**30. ¿Qué representa este tipo?

type Estado = "pendiente" | "hecha" | "cancelada";**


A. Un tipo unión de literales de cadena con tres valores posibles
